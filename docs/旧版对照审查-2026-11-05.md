## 初次审查发现（修复前证据，状态以上表为准）

### 1. 白名单规则遗漏 WebSocket（本轮独立化引入）

- 位置：`super-power-browser-plugins/runtime/access-policy.mjs:19`。
- 新的会话规则声明包括 `websocket`，但白名单的兜底拦截表达式为 `^https?://`，不能匹配 `ws://`、`wss://`。
- 本次实际调用 `installAccessPolicy` 捕获生成规则：未允许域名的 HTTPS 匹配拦截规则，WS/WSS 不匹配。恢复的旧插件动态规则主要用于 HTTP 资源改写，不能补齐此规则遗漏。
- 影响：不能把当前“仅允许指定网站”当作已覆盖所有声明的网络资源类型。实际浏览器握手场景还需要专项验收；此次没有向外部 WebSocket 发请求。
- 修复方向：补齐协议覆盖，保留本机桌面通信和自有后台例外，并验证允许/禁止域名、子域名、例外路径和 WebSocket。

### 2. 完整版本号的默认 UA 不一致（本轮完整版本号支持遗漏）

- 位置：`super-power-browser-server/core/src/main/java/com/superpower/browser/extension/ExtensionService.java:174`；桌面对应 `src/main/runtime/IndependentKernel.js`。
- 触发条件：发布 `144.0.7559.132` 这样的完整版本标签，店铺未填写自定义 UA。
- 桌面生成 `Chrome/144.0.7559.132`；后台仍无条件追加 `.0.0.0`，返回 `Chrome/144.0.7559.132.0.0.0`。
- 本次执行恢复插件原有的 `checkUserAgent` 方法，结果为 `checkUa=false`。它对主版本降位的兼容比较也不能消除该差异。
- 当前实际发布标签为 `144`，这一触发条件暂未命中；不能据此认为完整版本升级流程已经正确。
- 修复方向：后台、桌面和 Web 统一 UA 生成规则，保留旧版检测语义。

### 3. 任务栏颜色和编号可填写但未生效（既有缺口）

- 位置：`super-power-browser-web/src/views/mallManage/component/createMall.vue:33`；`super-power-browser-desktop/src/main/BrowserManage/BrowserHost.js:56`。
- 页面保存 `iconColor`、`taskbarNumber`，当前桌面只复制统一的 `branding/app.ico`；未发现运行路径消费这两个字段。
- 旧版 `rux-browser-master/src/main/zhanfubrowser/RuxToSbp.js:1187` 会读取 `show_sign_with_rgb` 并绘制店铺角标。
- 新品牌图标替换已经实现，但不等于旧版每店颜色/编号功能已经迁移。

### 4. 部分桌面动作仅返回成功，退出动作范围不同（既有缺口）

- 位置：`super-power-browser-desktop/src/main/BrowserManage/BrowserHost.js:79`。
- `FlashWindow`、`PlayVideoMp3` 只返回 `{accepted:true}`，未执行闪烁或播放。
- `ExitClient`、`closeAllMultiOpen` 与 `CloseBrowser` 共用 `close(id)`，实际只关闭当前店铺。旧版 `MultiModule.closeAllMultiOpen` 存在多实例退出/重新启动流程。
- `UploadCache`、`StartProxy` 则明确报未配置：完整缓存同步、供应商备用线路尚未接通。内置插件能启动不能证明这些操作等价。
- 修复方向：按动作分别实现实际行为；未实现的能力明确返回不支持，避免界面误认为已完成。

### 5. 下载期间关闭会等待整个启动完成（本轮按需安装扩大了影响）

- 位置：`super-power-browser-desktop/src/main/BrowserManage/BrowserHost.js:117`，`src/main/index.js` 的退出和会话切换处理。
- `close` 先等待 `pending` 启动任务，内核下载没有取消信号；`closeAll` 被退出客户端及会话切换调用。
- 隔离检查确认：启动 Promise 未结束时，关闭 Promise 不结束。代码中的下载超时为 10 分钟，安装锁等待上限为 15 分钟，慢网下退出可能长时间停住。
- 修复方向：为店铺启动加入取消状态，并处理同版本共享下载的订阅；关闭后不能继续启动该店铺，也不能取消其他店铺正在使用的下载任务。

## 已要求的独立化与功能差异

| 环节 | 当前旧版 | 当前新项目 | 审查结论 |
| --- | --- | --- | --- |
| 内核来源 | 站斧定制二进制、helper 和授权 | 开源补丁内核 144，上游预编译包 | 符合用户后来选择的“彻底独立”，不是原生算法原样复制 |
| 可用版本 | 126、130、137、140、144、150 | 当前后台只发布 144 | 版本集合未全量迁移；144 属于旧版支持的主版本 |
| 清单与分发 | 旧接口返回 link/MD5，远程 ZIP | 新接口、数据库版本目录、SHA-256、本地 ZIP/可选 S3 | 客户端获取流程对应；旧后台数据库和存储内部实现未知 |
| 下载时机 | 打开店铺时缺失才下载；预下载代码注释 | 打开店铺时按需安装 | 一致；新项目同样没有自动预下载 |
| 下载恢复 | 本地复用、断点续传、安装互斥 | 本地复用、续传、锁、临时解压、原子安装 | 主要流程对应，校验和失败恢复实现不同 |
| 已安装校验 | 可用列表命中后跳过全量 MD5 | 每次安装入口验证文件 SHA-256 | 实现差异；本机已安装 144 此次校验约 379 ms，不是公网下载测速 |
| 插件启动 | RBP、加密配置、旧原生桥和 WebSocket | RBP、加密配置、固定扩展 ID、自有 WebSocket | 主链路对应；移除旧原生桥是独立化要求 |
| 指纹 | 旧内核私有配置与算法 | 上游原生参数，部分网页接口由扩展限制 | 不等价；没有完整旧内核源码，不能宣称完全相同 |
| 选项 | 独立的部分指纹选项、旧原生接口 | Canvas/字体测量/WebGL 噪声联动，Android/指定 WebRTC IP/自定义字体和 GPU 字符串不可用 | 明确功能差异，不能当作全部迁移完成 |
| 店铺目录 | 旧桌面按店铺目录并记录 KERNAL.ini | independent/店铺/版本 | 独立隔离；切换版本不会自动继承全部 Local Storage/IndexedDB 等本地状态，Cookie 恢复不等于完整 profile 迁移 |
| 自有设备检测 | 旧插件包含自有设备直接通过分支 | 也必须通过代理出口检测 | 用户明确要求的差异，应保留 |
| 出口判断 | 多检测地址，固定 IP 任一匹配 | 对齐公开检测源与任一匹配；本地入口按实际出口 | 判断主体对应，不依赖旧厂商专有检测接口 |
| 线路提示 | 旧检测页有固定成功展示 | 与实际出口检测结果联动 | 已按用户要求改进；仍不等于供应商线路优化/完整测速 |
| 品牌与布局 | 站斧品牌 | 自有品牌；当前差异未修改顶部/侧栏蓝色布局及登录页 | 符合用户要求的品牌调整范围 |
