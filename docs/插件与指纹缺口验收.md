# 插件与指纹缺口验收（2026-11-04，0.2.7）

本轮以运行中的旧站斧、旧桌面的 `RuxToSbp.js` 和当前 RXMallHelper 5.1.78 为依据。只读取旧环境配置、在旧浏览器添加并关闭临时本地指纹测试页；没有修改或删除真实店铺。新功能使用独立临时店铺、代理和 profile 验证，测试记录随后删除。

## 指纹由哪里实现

链路是：新后台保存配置与稳定环境标识 → 桌面生成原生配置并交给 SDK 加密 → 专用 Chromium 内核处理网页可见指纹。店铺助手主要负责检测、代理与业务辅助。指纹不是依靠助手向网页批量覆盖 JavaScript 属性实现的。

Passkey 是另一条链路：旧助手通过 `chrome.debugger` 的 WebAuthn 虚拟认证器管理凭证，并在特定平台注册页捕获创建参数。这不代表 Canvas、WebGL 等指纹也由插件注入。

## 已修复并实测

| 项目 | 本轮结果 |
|---|---|
| UA Client Hints | 原先 UA 是所选版本，Client Hints 却暴露内核实际小版本及宿主系统版本；现按旧版下发 `user_agent_data`。Windows 137 实机核对通过 |
| WebGL | 去掉启动时无条件 `--disable-gpu`，实际恢复 Intel GPU 信息；支持关闭 WebGL，页面获取 context 返回 null。自定义 vendor/renderer 字段已接线，但未宣称所有组合已实机验证 |
| Canvas / Audio / Client Rects | 隐私模式同一店铺重复读取、重启后稳定；本次两个不同环境样本结果不同。真实模式两个不同 seed 的样本一致；不承诺随机扰动能保证全世界唯一 |
| 字体 | 按旧版传入 `full_font_list`。实测可过滤 Consolas、Times New Roman 等可选字体；内核仍保留部分基础字体，不能声称仅暴露自定义名单。默认候选名单按持久化 seed 固定，不调用旧平台字体接口 |
| 语音 / 语言 / 时区 | 按旧版 Windows 语音选择顺序处理：完整语言匹配、主语言匹配、en-US 回退，再追加 Google 语音；en-US、America/New_York 与语音列表实机通过 |
| WebRTC | 禁用时 createOffer 返回 NotSupportedError；真实模式可创建 offer。替换模式使用设备有效映射公网 IP，拒绝把回环/私网地址当公网替换；公网映射参数有自动测试，未进行外部 STUN 泄漏专项验收 |
| 记住密码 / 消息提示 | 记住密码关闭写入 Chromium 凭据服务设置；通知按旧版添加或撤销 HTTPS 自动允许规则，关闭意味着恢复询问。实际 Preferences 和 HTTPS Notification.permission 检查通过 |
| 书签 | 已验证书签栏、嵌套目录和“其他书签”保存到新后台；移除测试 profile 的本地书签文件后重开能恢复。修复初始化与新建书签竞争，以及删除根目录/未等待删除完成的问题；恢复完成后再显示检测页 |
| 访问范围 | 编辑页支持禁止域名或仅允许域名，传入旧版内核 `black_white_list`。实际黑名单拦截、白名单允许和拒绝、重开插件均通过；被拒绝时显示新品牌提示页 |
| 内部页面放行 | 实际旧配置通过 `exception_list` 放行 `chrome://`、`chrome-extension:`、`file://` 等；新项目已按相同机制处理。单纯填写 `white_schemes` 不足以保证该内核可打开插件管理页 |
| Passkey | 新后台下发 `front_addendum_info` 中两个开关。真实 WebAuthn API 在本地响应夹具中完成注册、助手捕获、后台保存、清除本地凭证、重开、恢复及签名认证；“使用本地 Passkey”开启后虚拟注册认证器不再启用 |
| 输入框锁定 | 编辑页设置能保存并控制账号助手。按旧版只对密码区域添加鼠标遮罩；实测开启时鼠标不能点入密码框，关闭后可正常编辑。它不是账号框 readonly，也不是键盘或脚本安全隔离 |
| 翻译辅助 | TikTok 本地响应夹具验证 `translate="no"` 限制会被移除；空的非翻译节点配置按数组返回。此脚本本身不提供翻译模型，整页翻译仍由浏览器与可用网络服务完成 |
| 配置校验 | 保存时检查枚举、开关类型、字体列表、域名、语言、时区和 UA 主版本，避免保存成功但启动才因明显非法字段失败 |

Passkey 测试页面使用 Amazon URL 匹配旧插件的既有注入规则，但页面响应完全由本地测试夹具提供；没有向真实 Amazon 创建账号、注册凭证或提交登录。通过的是实际插件和浏览器 WebAuthn 链路，真实平台风控与所有站点兼容性仍需单独验收。

## 仍然存在的边界

- 完整浏览器缓存跨机器上传/下载尚未实现；现有 Cookie 同步、书签同步、Passkey 保存不能替代 Local Storage、IndexedDB 和整个 profile 的迁移。能力接口明确返回 `fullProfileSync=false`。
- 供应商备用线路缺少真实节点与切换服务，`lineSwitching=false`；切换请求返回明确错误，不制造虚假的“切换成功”。TCP Ping 只代表当前代理入口连通性。
- 第三方插件市场、远程下载更新和审核流程没有新服务。两个内置助手的部署、版本更新和校验已经实现，能力标识为 `pluginDistribution=bundled`。
- 员工网页元素限制仍保留旧脚本与读取接口，但没有完整规则管理和白名单审批工作流；本次验证的是店铺级内核域名访问范围，不能算整个员工权限产品完成。
- 翻译节点例外、汇率、推荐列表等原厂配置没有自动复制；页面翻译服务、站点目录、平台专用规则需要由新系统提供配置。
- 当前内核实测的屏幕尺寸、CPU 核心数和内存仍随宿主环境；旧桌面对应字段也没有完成映射。界面将原“分辨率”改为“窗口尺寸”，去掉没有实际映射的 MAC 输入，不再暗示已伪造这些属性。
- Windows 137 是本轮原生验证范围。Mac/Android 的 UA Client Hints 生成有自动测试，但不等于已把 Windows 内核变成真实 Mac/Android 运行环境。
- 插件业务主体仍是旧版编译后 JavaScript 的可构建移植与适配，不是已完成的全量独立源码重写。
