## 接口证据与限制

现场观察到店铺计数 `/api/v1/bindMall/countMall`、站点目录 `/api/v1/siteInfo/getSiteTreeByCategoriesV2`、设备列表 `/api/mall/agentIp/showV2`、设备商品目录 `/api/mall/agentIp/getEquipmentResourceV3`、订单列表 `/api/v1/money/buyRecord/show`、角色权限 `/api/v1/company/permission/getPermissionNodes` 与 `/getPermissionRoles`、店铺授权查询 `/api/v1/bindMall/getBindMemberList` 等请求。

这些响应普遍是 `format=1` 的加密数据。本次抓包证明请求路径、方法、参数名和触发页面，不能单独证明解密后完整字段；字段关系需与原源码消费位置共同核对。未通过提交真实订单或修改权限探查写接口。

现场角色说明把查看店铺列表与打开店铺等操作捆绑，且普通成员只能查看获授店铺绑定的设备。新权限模型按本次核心操作细分，所有者权限显式定义；成员缺少角色时默认无操作权限。

## 运行资源与临时旧接口边界

源仓库 `Core/` 仅有版本清单；现有系统设置页揭示本机另有已安装内核目录，其中可见 130、137、140、144、150 版本。这证明存在本机运行资源，不代表已有内核源码或可独立签发凭据。新应用使用自己的用户数据目录，不复用原店铺登录态目录。

用户已明确：**仅内核和插件可暂时调用旧接口**。用集中适配层获取内核清单、原生凭据及必要插件，代码以 `TODO(runtime-replacement)` 标明后续替换点；凭据通过配置提供。设备供应、充值、购买和支付使用新契约，缺少供应商或商户配置时明确返回未配置，不调用旧业务接口或伪造成功。

已观察 UI 不等于已验证写操作、支付到账、设备交付或新程序真实内核启动。后续按各模块的测试和实际接入情况更新验证记录。
