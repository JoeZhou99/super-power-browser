# 代理管理

设备管理保留平台设备、专享平台设备、购买设备和设备回收站。用户自行购买的代理统一放在代理管理，不再在设备管理重复展示“自有设备”。代理管理有代理列表、动态代理两个入口；代理回收站通过列表按钮进入。

## 添加与使用

- 支持 HTTP、HTTPS、SOCKS5、SSH，域名、IPv4 和方括号包围的 IPv6。SSH 使用账号密码认证。
- 单条添加可设置名称、供应商、地域、静态/动态类型、到期时间、备注、认证和换 IP URL；到期时间可不填。
- 批量添加单次最多 500 条，支持 `host:port`、`host:port:user:password`、`user:password@host:port`、`protocol://user:password@host:port`，可附加 `{备注}` 和 `[换IP URL]`。未写协议时使用选择的默认协议。预览会提示错误；整批校验通过后才写入。
- 同一网关、端口的不同会话账号独立保存，不会按地址覆盖。
- 编辑时会读取并回填已保存的账号密码，密码默认遮罩，可点眼睛查看；读取失败时禁止保存，并支持重新读取。每次关闭编辑窗口都会清理页面中的凭据。编辑时留空密码保留已有认证；清除认证、清除换 IP URL 需勾选对应选项。列表、普通详情及 Excel 导出不包含密码和换 IP URL。
- 店铺的“网络配置”可从已添加代理或平台设备中选择，也可解除绑定。一个代理可以绑定多个店铺，已绑定的资源须先解绑才能删除。
- 在桌面客户端可检测连接和批量检测，保存出口 IP、国家、检测耗时及时间；纯 Web 页面不能代替用户本机检测。换 IP URL 由桌面单独发出请求，不携带平台登录信息，不自动跟随重定向。共享代理换 IP 前会提示影响。

“动态代理”管理的是用户供应商提供的动态网关、会话账号及换 IP URL。界面不销售供应商流量，不显示无法核实的剩余流量，也不保证换 IP 请求会改变出口地址。供应商的会话规则和本地网络可达性仍由实际服务决定。

## 数据与权限

沿用现有 `device` 中 `ip_type=2` 的记录，`web_type=1` 为动态、`2` 为静态。V18 迁移新增代理元数据与检测结果字段，不复制设备或重建绑定。旧 `/agentIp/all?type=2` 和对应回收站链接跳转至代理管理。

代理管理复用 `device.view`、`device.edit` 和 `device.export` 权限。店铺网络绑定仍要求 `shop.edit`、`device.view`。记录按企业隔离；密码和换 IP URL 通过现有数据密钥加密保存。编辑窗口通过 `/{id}/credentials` 仅读取账号密码，要求编辑权限，响应禁止缓存；过期代理也可以编辑，回收站代理须先恢复。连接配置接口另用于有编辑权限的客户端检测。

接口前缀为 `/api/proxies`：列表/新增、`/{id}` 详情/编辑/删除、`/import` 批量添加、`/{id}/restore` 恢复、`/{id}/environments` 查看绑定、`/{id}/connection` 获取连接、`/{id}/check-result` 写入检测结果。

## 删除与自动续费

设备删除和回收站确认文案沿用旧 Web 项目的流程：普通删除进入回收站，永久删除不可恢复；前端删除只提交删除请求，不额外调用自动续费接口。

本次不改计费或自动续费后端。当前新后端已有行为是：进入或恢复回收站都会将 `auto_renew` 置为 false，续费任务只查询未回收的平台设备。永久删除不会保留可续费的设备记录。旧 Web 源码没有服务端实现，不能据此断言旧服务端是否采用相同规则。

用户自备代理没有平台购买/续费功能，其供应商扣费由用户在供应商处管理，删除本项目记录不会取消供应商订阅。

## 验证与上线

此次验证覆盖代理文本解析、真实本地 HTTP/SOCKS5/SSH 转发、换 IP 请求限制、后端权限与密文保护、批量原子写入、V17→V18 升级保留绑定，以及模拟 API 下的页面添加、检测、回收恢复和店铺绑定。

Web 使用 `npm run build`；桌面新增 `ssh2` 依赖，更新依赖后可用 `npm run test:proxy` 验证连接。后端当前机器使用 JDK 17 执行 `mvn -o '-Djava.version=17' -pl api -am test`，生产仍以项目的 JDK 21 为准。

部署时先备份数据库，再更新后端运行 Flyway V18，同时更新 Web 和桌面客户端。此次开发验证使用 H2 和本地模拟网络，未操作生产数据库或真实客户代理；生产 MySQL 和实际供应商代理仍需部署验收。
