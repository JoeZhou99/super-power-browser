# 中继池与自动选路

用户新增、编辑代理时，不再填写中转、备用线路、资源代理和域名分流。用户只填写自己的出口代理，不再选择网络加速分组；企业授权决定候选中继。相关旧表单已删除，没有移入高级设置；协议本身需要的 TLS、SS、VMess、VLESS 参数继续保留。

## 使用流程

1. 运营人员进入独立 `super-power-browser-admin` 的“代理管理 → 中继分组”，维护名称、唯一编码、备注、启停和候选数量；在组内添加已部署并开启认证的 HTTP、HTTPS、SOCKS5 或 SS 节点。SS 必须填写与服务端一致的加密方式及密码，不能把 SS 端口填写为 SOCKS5。
2. 在同一页面给企业授权线路组，可设置授权到期时间。有效授权用于服务器自动选择候选，客户表单不展示分组下拉框。
3. 静态代理自动使用企业获授权的中继分组。HTTP、HTTPS、SOCKS5、SS、VMess、VLESS 出口支持平台中继；SSH、SSR、SOCKS4/4a 和动态出口暂不支持。
4. 打开店铺时，业务后端重新校验授权，按分组 ID 和组内节点顺序轮流下发，遵守各组候选数量上限，总计最多 4 条。每个候选使用相同出口代理，只替换前一跳中继。
5. 本地代理准备好后先打开店铺检测页，出口检查在后台进行，页面短轮询同一次检查结果。优先验证当前线路，失败才依次尝试其他授权候选，不在开窗前测速全部线路。检测失败保留页面，用户可以重新检测；所有候选都失败时不进入业务网站。切换备用前做隔离出口校验，切换后复验真实运行线路。启动后每 60 秒检查当前出口，连续 3 次失败才尝试其他候选，成功切换后有 120 秒冷却时间；运行中的健康检查不依赖网站 HEAD 或重新解析语言、时区。

```text
店铺浏览器 → 本地网络门禁 → 本机 Xray → 中继 A / 中继 B → 原绑定的出口代理 → 网站
```

已打开店铺的检测页在分配到中继时显示“加速线路”（只有一个候选也显示），显示所属分组、节点、延迟和采样时间。客户可以测速、手动选择并锁定线路，或恢复自动。客户端不会因为另一条线路略快而切换健康连接。手动锁定仅禁用自动切线，当前线路的出口健康检测持续运行；点击恢复自动后允许故障切换。锁定仅在本次打开店铺期间有效。测速使用临时代理会话，不切走当前店铺正在使用的线路。

## 延迟如何理解

- 首跳 TCP 延迟：本机到中继监听端口建立 TCP 连接的耗时，不包括出口代理和目标网站。
- 网站响应耗时：通过完整代理链对店铺启动网址发送无 Cookie、无店铺令牌的 HEAD 请求耗时；同时验证代理实际出口。它不是单纯的网络 ping，也不表示业务登录成功。
- 显示采样时间；失败或未测显示不可用，不填入虚假的 `0ms`。

入口连接和网站 HEAD 测速由用户主动触发，不作为开店及自动故障切换的必经条件。中继线路启动出口检测最多 20 秒，运行检测最多 14 秒，普通代理沿用 12 秒总预算与单站 8 秒预算。中继检测每次最多同时请求两个检测服务，首个通过出口验证的结果会取消其余请求。检测页每秒查询状态，不让桌面 RPC 等待整轮公网检查；重复初始化事件和插件重载不会重复开启检查。用户显式点击“重新检测”会开启新的真实探测，即使上次已成功也需要重新完成确认；进行中的重复请求复用同一轮。启动选路有 45 秒协作取消预算；已提交的本地代理重启会等待完成或恢复后再收尾，不留下后台继续切换的任务。失败诊断记录候选编号、阶段和耗时，区分出口校验失败与检测服务超时，不保存中继密码。

## 开窗与语言时区

自定义语言、时区的店铺直接先开内核检测页。自动设置优先使用本店铺、同一固定出口最近 24 小时验证过的地区缓存，窗口打开后仍需实际验证当前出口及语言时区一致。缓存只保存地区设置，不代表网络可用；更换出口、凭据、指纹配置、内核版本或缓存过期后失效，动态出口不复用。

首次没有自动地区资料时先显示本地检测窗口；它不加载店铺 Cookie 或真实 profile。地区检查通过后才以正确语言、时区启动店铺内核；失败保留重试，关闭即取消。若新检测的地区与缓存启动值不一致，本次禁止进入网站，更新缓存并提示关闭重开，不在运行中静默修改指纹。

浏览器与资源分流均使用独立本地入口，验证前阻断外部业务流量。首次检测和手动切线必须由当前插件、当前检查轮次完成确认后放行；已授权会话自动故障切换需实际出口复验通过才能恢复。签名 bootstrap 中指定的精确 HTTPS 后端 origin 作为控制面直连，以完成授权；业务站点仍受门禁。代理出口检查本身使用底层 Xray 的鉴权入口，不受业务门禁阻塞。窗口已打开与出口已通过是不同状态。

旧版下发的中继入口可能已经映射至指定设备，不能直接当作可连接任意出口的通用中继。接入新池需要确认协议、认证、加密方式，以及它能否连接用户绑定出口的代理端口。单独连通中继或 TCP 端口不能证明完整代理链可用。

固定 IP 配置继续严格比对实测出口；只有域名入口且未填写映射 IP 时，以本次会话首次验证的出口作为基准，后续中继必须保持一致。这个基准不能证明它就是用户购买时约定的 IP，建议固定代理填写准确的映射出口 IP。

## 后台与旧数据

业务后端不再接收用户的 `proxyOptions.transit`、`alternatives`、`resourceProxy`、`routing`。旧数据库里的加密配置读取时剥离这些字段，下一次保存时清理存储。不会尝试把用户旧中转凭据自动转成平台共享节点。

Xray 内部仍使用 `transit` 和 `alternatives` 表达授权候选。这些连接信息只能由业务后端根据平台池和企业授权组装，不是用户可编辑的配置。普通代理列表及编辑凭据接口不返回中继密码；启动和连接接口需要下发实际认证信息供本机转发使用。

独立运营后端提供中继分组、节点和企业授权管理；业务后端根据企业授权自动组装连接，不再保存设备到组的绑定。客户 API 拒绝 relayPoolId（包括 null）。两套服务独立构建和发布，共用数据库。V25 删除设备 relay_pool_id 绑定列，给原 relay_pool 增加 code/remark 与唯一索引；旧分组编码默认用原 ID。V26 放开 SS 节点协议约束；V27 用 CASE 约束替换会引用已关闭迁移连接的 H2 IN 约束，保留节点、密码、排序和授权，不修改已执行的 V26。SS 节点需填写实际密码与加密方式，不使用 SOCKS5 账号。运营后台启动只读验证共享表和业务 Flyway 历史中的 V27 成功记录；未完成时明确拒绝启动。两个服务必须使用相同的 `APP_DATA_KEY`，节点密码按现有 AES-GCM 格式加密。运营审计不保存密码和密文。

启用中继池的店铺不应用运营域名分流规则，所有网站请求均走该店铺绑定出口。未启用中继池的店铺保留既有运营直连规则；没有专用资源代理时，资源/CDN 请求使用主出口，不因删除用户配置而阻止开店。

## 发布与运行边界

更新业务服务并完成 V27 迁移，再更新独立运营服务、运营页面、用户页面及桌面插件。运营服务不运行迁移或改写迁移历史。已有店铺使用启动时的候选快照，运营修改在下一次打开时生效。不要为了更新代码直接结束用户正在操作的店铺。

没有有效授权（含授权撤销/到期）时，直接连接原出口代理。有有效授权但相关组全部停用或没有启用节点时，新连接明确返回不可用。动态代理和不支持协议直接连接原代理；过期/回收设备不能开店。所有候选网络不通时留在检测界面，不绕过出口代理。

本次实现提供平台库存和企业授权、客户端本地选路与故障切换。以下能力仍需运营或后续建设：

- 必须实际购买或部署中继网关，配置代理服务、账号、端口、防火墙和带宽。本项目不会自动购买 VPS、自动安装远端代理或生成可用节点。
- 候选由运营排序和数量限制下发；没有基于全网负载、带宽余量、地域或成本的服务端动态调度。客户端延迟代表当前客户所在网络，不代表所有客户。
- 定时检测和连续失败阈值意味着故障恢复需要时间。当前 Xray 切换会重建上游，可能打断下载、上传、WebSocket 等长连接；不承诺无感切换。
- 中继不能修复出口 VPS 宕机、出口账号到期、目标网站故障或客户本地断网。共享节点还需要运营容量规划、监控、带宽限额和网关级访问限制。
- 如果真实运行线路的实测出口改变，客户端会停用本地代理并关闭该店铺；隔离候选不匹配时只拒绝该候选。周期检测仍无法承诺在检测到出口变化之前阻断所有请求。
- 当前企业授权控制应用内配置读取。节点静态认证信息已下发到获授权客户端后，撤回企业授权不会立即撤销网关上的凭据，也不会中断已运行的快照。网关级即时撤销需要为企业签发独立凭据或短期令牌，并在网关执行限额和撤销；首版没有实现这套网关凭据系统。

旧版可参考的行为是后台下发候选、失败尝试下一条和手动切换。本次增加了桌面进程持续监测、连续失败阈值和冷却；没有照搬旧版测速时临时切走店铺实际线路的做法。

## 管理页面与数据含义

“代理管理”包含客户代理 `/proxy/list`、中继池 `/proxy/relays`、中继分组 `/proxy/groups`。旧 `/network/relays` 跳转至中继分组，沿用 relay_pool 数据模型。

客户代理是客户自行添加的出口，不是平台销售库存。点击 IP 查看详情、绑定店铺、最近检测结果、候选加速配置；支持复制不带凭据的端点及跳转相关分组。运营不能查看密码、删除客户代理或切换运行线路。不展示未采集的 VPS CPU/内存、销售订单、实时负载、geo/欺诈评分。

中继池平铺实际节点，按组、协议和启停筛选，进入所属组添加/编辑节点。分组编码支持英文字母、数字、下划线和短横线，编码唯一；候选上限不是节点承载配额。组内维护节点和企业授权，只建节点但未授权企业不会启用加速。

列表“自动加速”和候选预览表示配置，不代表已连通或当前正在使用。实际线路以已打开店铺的运行快照为准；最近检测值含采样时间。后台不远程强制切客户线路。

## 验证范围

业务覆盖自动候选公平轮询、协议/企业隔离、无授权/停用/空节点/到期状态、拒绝客户绑定及 V24→V25 迁移。运营覆盖只读权限、脱敏、筛选分页、分组编码唯一性、节点与授权版本校验。桌面和插件覆盖同出口验证、隔离测速、连续故障切换、手动锁定、恢复自动和分组展示。联调使用独立数据库、隔离页面和本机模拟代理，不修改真实客户数据；不等同于生产线路容量验收。本机 Java 17 通过命令行覆盖版本构建，项目 Java 21 声明未修改。
