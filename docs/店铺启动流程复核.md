# 店铺启动流程复核

> 历史基线：本文描述 137 内核阶段的启动复核。当前已切换为独立 Chromium 144、自有 Electron 和插件 0.3.1，不再使用本文所述旧原生管道、授权及 Secure Preferences 启用方案。当前启动、下载取消和桌面动作见 [独立内核说明](../super-power-browser-kernel/README.md) 与 [2026-11-05 对照修复](旧版对照审查-2026-11-05.md)。历史结果不能直接视为独立 144 全量验收。

2026-11-04。修改限于新项目，旧站斧及真实亚马逊店铺保持原状。

## 对照旧版的启动链路

| 环节 | 旧版参考 | 新项目实现 |
| --- | --- | --- |
| 插件解压 | `rux-browser-master/src/main/pluginManage/PluginService.js` | 每个店铺独立的 `UserFile/<店铺ID>/RBP/RXMallHelper`、`RXAccountManage`，从新项目插件包解压 |
| 启动配置 | 同文件 `initPluginV2` | 按目录生成扩展 ID，生成 `config.dat` 和加密 `init.json`；注入当前店铺、代理、插件会话和桌面通信端口 |
| 内核安装态 | `src/main/zhanfubrowser/RuxToSbp.js` 的 `setBrowserInfo` | Preferences 设置开发者模式，Secure Preferences 写安装态；内核参数 `load-extension` 指向当前店铺的插件目录 |
| 通信与检测 | 旧插件后台及桌面通信处理 | 原生管道连接内核，经过认证的 WebSocket 连接插件；插件打开检测页，检查出口及 UA，通过后自动打开店铺 |
| 已运行店铺 | `src/main/BrowserManage/BrowserHost.js` | 复用当前进程并恢复窗口；旧进程迟到的退出回调不能清理新实例 |

137 内核的全新 profile 会重置预写的开发者模式，导致两个扩展都因 `unsupportedDeveloperExtension` 被禁用。新项目保留上述旧版加载链路，在内核启动后通过其正式扩展配置接口初始化开发者模式并确认两个内置扩展已启用。初始化页面就绪后才调用接口，完成后关闭临时配置页；不关闭内核的安全校验功能。

修复了启动进程却隐藏主窗口的问题。现在确认对应 PID 的原生主窗口可见后继续启动；“更多 → 显示浏览器窗口”可以恢复最小化窗口，不重复启动实例。启动失败原因写入该店铺的运行诊断文件。

插件 0.2.6 同时修复线路检测状态变化后图标未刷新颜色的问题，使图标与成功／失败文字同步。

## 实际验证

使用全新临时店铺、独立本地转发代理和本地模拟登录页完成 11 个步骤：首次窗口显示、真实公网出口及 UA 检查、自动打开模拟店铺、模拟账号填充、最小化后恢复同一进程、关闭清理、代理故障后重开、阻止访问店铺、修复代理后重新检测、再次关闭重开、原生窗口退出后桌面状态清理。测试使用真实直连公网出口经隔离代理转发，未伪造检测响应，未修改 Clash。

临时店铺和代理记录均已删除。当时桌面 12 项自动测试通过，另有此前通过的后端 26 项和插件 12 项测试。测试代码、验收脚本及截图报告已按要求清理，此处保留历史验证结论。

## 当前 Clash 的实际结果

通过 Clash 本地控制接口只读核对：模式为 `rule`；`amazon` 域名规则指向代理组，国内 IP 规则为 DIRECT，兜底规则仍指向代理组。初次选择的 `ipwho.is` 和 `api.ipify.org` 命中日本节点却未返回结果，此结论只针对这些检测地址，不能扩大为全部代理不可用。

随后连接已启动的旧站斧 137 内核，读取实际检测页面、运行中的 Vue 状态及检测地址配置：当前旧店铺为平台设备，绑定及显示 IP 都是 `154.90.137.210`，IP／UA 检查均为 true。本地网络单独显示中国广东深圳。未点击真实店铺的业务操作。

旧站斧使用 `myip.ipip.net`、`lumtest.com/myip.json`、`ifconfig.me/ip` 及旧厂商自己的 whoami 接口。新项目对齐前三个公开 HTTPS 地址，不依赖旧厂商服务；支持文本 IP、JSON IP、中文地域文本。固定公网设备按旧版“任一检测地址匹配即可”规则；本地入口及动态设备必须取得真实公网 IP，按配置顺序选取结果。检测均经过配置代理，无直连回退。

经当前 Clash 请求旧版公开地址实测：`myip.ipip.net` 返回 `218.18.100.69`（中国广东深圳），`ifconfig.me/ip` 返回 `94.177.131.137`，lumtest 连接重置。因此规则模式确实使不同检测地址出现不同出口。新桌面返回各检测地址与结果，并在设备“检测代理”结果中提示多出口；检测页的实际 IP 不代表所有站点都使用同一个出口。

自有代理仍按用户要求严格检测：全部检测失败则阻止打开店铺，不把 `127.0.0.1` 当作公网出口。本次对齐后当前 Clash 可通过实际公网检测；“日本”仍是设备配置地域，不是检测结果的国家证明。
